DNSを
図で触って理解する

人が入力するのは www.example.com のような名前。でも通信にはIPアドレスが必要です。DNSが「名前 → IPアドレス」をどう探すのか、問い合わせが進む一本道の図で確認します。

DNSの問い合わせを図で追う

学習用シミュレーションです。実際のDNSへ通信はしません。次へを押すか、図の各場所をタップして進めてください。

名前解決の全体像開始前
ブラウザで名前を入力すると、まずDNSで通信先のIPアドレスを調べます。
DNSが返した答えwww.example.com
203.0.113.10
青 = 今ここ　緑 = 完了　キャッシュONではルート/TLD/権威DNSを省略します。

ドメイン名は右からたどる

DNSの階層は、右側ほど大きな分類です。

wwwホスト / サブドメイン
exampleドメイン名
comTLD

たとえば www.example.com なら、ルートから .com のDNSを知り、次に example.com の権威DNSを知り、最後に www のIPアドレスを取得します。

キャッシュがあると短くなる

一度調べたDNSの答えがDNSキャッシュに残っていれば、ルートDNS・TLD DNS・権威DNSまで問い合わせる必要がありません。上の「キャッシュに答えがある」をONにすると、図そのものが短くなります。

DNSレコードには TTL が設定され、キャッシュをどのくらい保持するかの目安になります。

DNSレコードはIPだけではない

A名前 → IPv4アドレス
AAAA名前 → IPv6アドレス
CNAME別の名前への別名設定
MXメールを受け取るサーバー

よくある勘違い

DNSがWebページを送るわけではありません。DNSで通信先のIPアドレスなどを調べ、そのあとブラウザがHTTP / HTTPSでWebサーバーへ接続します。
