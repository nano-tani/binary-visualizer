CookieとCacheを
図で触って理解する

どちらもブラウザに何かを残しますが、目的は別です。Cookieはログイン状態などの識別情報を次のリクエストへ持たせ、Cacheは画像やCSSなど同じデータの再取得を減らします。

違いを一言で

Cookie = 状態・識別情報

サーバーが Set-Cookie で保存を指示し、ブラウザは条件が合う次回リクエストで Cookie ヘッダーを送ります。ログインセッションの識別子などに使われます。

Cache = データの再利用

レスポンスの保存条件に従ってHTML・CSS・画像などを再利用します。必要ならETagでサーバーへ更新確認し、変わっていなければ304を受けて保存済みデータを使えます。

実際に出てくるHTTPヘッダー

Cookieを保存させるSet-Cookie: session=abc123; Secure; HttpOnly; SameSite=Lax

サーバーからブラウザへのレスポンスです。

Cookieを送り返すCookie: session=abc123

条件が合うリクエストでブラウザからサーバーへ送られます。

一定時間キャッシュするCache-Control: max-age=3600

期限内ならネットワークへ再取得しなくてよい場合があります。

変更されたか確認するETag: "v7"
If-None-Match: "v7"
HTTP/1.1 304 Not Modified

変更なしならレスポンス本文を送り直さず、保存済みデータを使えます。

Cookieにパスワードをそのまま入れる？

一般的なログインでは、Cookieにパスワードそのものを保存するのではなく、サーバー側のセッションを識別する値などを持たせます。さらに Secure、HttpOnly、SameSite などの属性で送信条件やJavaScriptからのアクセスを制限できます。

Cookieがある = 安全、ではありません。値の設計、HTTPS、期限、属性、サーバー側のセッション管理を合わせて考えます。

304 Not Modified の意味

304は「キャッシュそのものをサーバーが送り返した」という意味ではありません。ブラウザが If-None-Match などで確認し、サーバーが「前に持っている版のままでよい」と答えるレスポンスです。ブラウザは手元のキャッシュを再利用します。
