1分で読む説明

検索から来た人も、ここだけ読めば要点がつながるように書いています。

Cookie

サーバーはSet-Cookie Response headerでCookieを設定できます。ブラウザはDomain/Path/Secure/SameSiteなど条件に応じて後続RequestへCookie headerを付けます。

HttpOnly / Secure / SameSite

HttpOnlyはJavaScriptからのCookieアクセスを制限し、Secureは安全な通信でのみ送信する条件、SameSiteはcross-site Requestでの送信条件に関わります。用途に応じた設定が必要です。

HTTP Cache

Cache-Controlなどで保存・再利用のルールを伝えます。ETagを保存していればIf-None-Matchで再検証し、表現が変わっていないとサーバーが判断した場合304 Not Modifiedを返せます。

304の本文

304は通常、保存済み表現の本文そのものを再送するResponseではありません。クライアントは既存Cacheを再利用します。

COMMON MISUNDERSTANDINGS

よくある勘違い

「Cookie = Session」Cookieはブラウザ側の保存・送信機構。Sessionはサーバー側状態を含む別の設計概念です。
「304はキャッシュ本文を返す」304は保存済み表現を再利用するためのメタデータ中心の応答です。
