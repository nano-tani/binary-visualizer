HTTPレスポンスの最初には、サーバーが処理結果を数字で返します。200・301・404・500などを切り替えて、ブラウザがその結果をどう受け取るか見てみます。

ステータスコードを切り替えて通信を見る

「次へ」「自動で見る」は図の上です。コードを選ぶと、URL・レスポンスヘッダー・ブラウザの動きも変わります。

最初の数字で大分類できる
1xx処理途中の情報
2xx成功
3xx追加の処理・転送など
4xxクライアント側の要求に関する問題
5xxサーバー側の処理失敗


よく見るコード
200OK要求が成功し、通常はレスポンス内容が返ります。
201CreatedPOSTなどで新しいリソースを作成できたときによく使います。
204No Content成功したが、返すレスポンス本文がない場合です。
301Moved Permanently別URLへ恒久的に移動したことを示し、Locationヘッダーを使えます。
304Not Modified条件付きリクエストに対して「変更なし」。キャッシュ済み内容を再利用できます。
400Bad Requestリクエストの形式や内容をサーバーが適切に処理できません。
401UnauthorizedHTTP認証が必要、または認証情報が不足・無効です。
403Forbidden要求は理解したが、サーバーがアクセスを拒否します。
404Not Found指定したリソースが見つかりません。
429Too Many Requests短時間に要求が多すぎる場合などに使われます。
500Internal Server Errorサーバー内部で予期しないエラーが発生しました。
503Service Unavailable一時的にサービスを処理できない状態です。


「4xx = ユーザーのミス」とは限らない
4xxは「クライアントから届いた要求を、そのまま成功として処理できない」という分類です。リンク切れで404になるように、原因がWebサイト側の設定や実装にあることもあります。5xxも同様に、原因調査ではレスポンスコードだけで決めつけずログや経路を確認します。
