3-way handshakeを
図で触って理解する

TCPは、いきなりアプリのデータを送り始めるのではなく、まずSYN・SYN-ACK・ACKの3段階で接続を作ります。図を進めながら、両側の状態がどう変わるか確認します。

SYN → SYN-ACK → ACK を追う

「次へ」「自動で見る」は図の上です。4段階目で接続確立、5段階目で実際のデータ送信まで進みます。

3回で何をしている？

1. SYNクライアントから「TCP接続を始めたい」と通知し、自分側の初期シーケンス番号を伝えます。
2. SYN-ACKサーバーが「受け取った。こちらも開始できる」と返し、サーバー側の初期シーケンス番号も伝えます。
3. ACKクライアントがサーバー側のSYNも受け取ったことを返し、接続がESTABLISHEDになります。

シーケンス番号も一緒に見る

実際の番号は接続ごとに変わります。ここでは理解しやすい数字を使っています。

SYNクライアントの開始番号Seq = 1000
SYN-ACKクライアントのSYNを確認し、サーバーの開始番号も提示Seq = 5000 / Ack = 1001
ACKサーバーのSYNを確認Seq = 1001 / Ack = 5001

SYNはシーケンス番号を1つ消費するため、たとえば Seq = 1000 のSYNに対する確認は Ack = 1001 になります。

接続確立後にデータを送る

3-way handshakeが終わると、両側は ESTABLISHED 状態になり、そのTCP接続上でHTTPなどのアプリケーションデータをやり取りできます。HTTPSの場合は、このあとTLSのやり取りが行われます。

3-way handshakeは暗号化やログイン認証ではありません。TCPで双方向通信を始めるための接続確立です。

なぜ2回ではなく3回？

クライアントのSYNがサーバーへ届き、サーバーのSYN-ACKがクライアントへ戻るだけでは、サーバー側から見ると「自分の返事がクライアントに届いた」とまだ確定できません。最後のACKが返ることで、双方が相手の開始情報を受け取った状態になります。
