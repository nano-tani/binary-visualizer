同じIP・ポートを使う通信でも、データの届け方には違いがあります。TCPは確認や再送をしながら確実性を高め、UDPはそれらをプロトコル自身では行わず、軽く素早く送ります。

TCPとUDPの考え方

TCP

接続を作り、データの順序や到達を確認しながら送る方式です。途中でデータが失われた場合は再送できます。アプリからは順序どおりのバイト列として扱いやすいのが特徴です。

UDP

UDP自身は接続確立、到達確認、順序制御、再送を行いません。そのぶん処理が少なく、遅延を抑えたい用途で使いやすい方式です。必要な信頼性はアプリ側で追加できます。

よく使われる場面

TCP: HTTPS / SSH / メールなどデータを欠けずに扱いたい通信で広く使われます。HTTP/1.1やHTTP/2はTCP上で動きます。
UDP: DNS問い合わせなど通常のDNS問い合わせではUDPがよく使われます。状況によってTCPが使われることもあります。
UDP: 音声・ゲームなど古いデータの再送より、最新データを早く届けることを優先する設計で使われることがあります。
UDP上に信頼性を作る例: QUICHTTP/3で使われるQUICはUDP上で動きますが、QUIC自身が再送や暗号化などの機能を持ちます。

「TCPなら絶対届く」ではない

TCPは再送や確認によって信頼性を高める仕組みです。ただし、回線断や相手サーバー停止などが起きれば通信は失敗します。またTCPが確認するのは通信上のデータであり、「アプリが処理を完了した」ことまで保証するわけではありません。
