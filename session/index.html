HTTPはstateless

HTTP semanticsでは各Requestは独立して理解できるstatelessな設計です。Webアプリが「ログイン中」を扱うには、Cookie、token、server-side Sessionなど追加の仕組みが必要です。

server-side Sessionの例

ログイン成功後、サーバーが推測困難なセッションIDを発行し、ユーザー状態との対応をサーバー側で管理します。ブラウザにはそのIDをCookieとして保存させる設計が一般的です。

セキュリティ

セッションIDが盗まれると乗っ取りにつながるため、HTTPS、Secure/HttpOnly/SameSite、十分なエントロピー、ID再発行、期限、サーバー側無効化などが重要です。

Sessionだけが唯一の方法ではない

すべてのWeb認証がserver-side Sessionを使うわけではありません。署名付きtoken等を使う設計もあります。このページでは初心者向けに典型的なSession方式を扱います。

COMMON MISUNDERSTANDINGS

よくある勘違い

「Cookieにusername=aliceとあればalice本人」ブラウザから届く値は利用者が変更できる前提で検証します。単純な自己申告値だけで本人認証しません。
「ログアウトはCookieを消せば完了」server-side Session方式ではサーバー側のSessionを無効化することが重要です。
