CookieとSessionは同じものではない

Cookieブラウザ側に保存される小さな情報です。セッション方式では、セッションIDをCookieに持たせる設計がよく使われます。
Sessionログイン中のユーザー情報などをサーバー側で管理する仕組みです。CookieのIDを手掛かりに対応するSessionを探します。

ログアウトすると何が起きる？

ログアウトでは、サーバー側のSessionを無効化・削除し、ブラウザ側のセッションCookieも期限切れにするのが基本です。Cookieの文字列が残っていても、サーバー側で無効ならログイン済みとは扱われません。

重要なのは「Cookieが本人」ではなく、CookieのセッションIDをサーバーが照合して初めてログイン状態になることです。

セキュリティで気をつけること

セッションIDを盗まれると、本人になりすまされる危険があります。そのため実運用ではHTTPSを使い、Cookieに Secure / HttpOnly / SameSite などを設定し、ログイン後のセッションID再発行や有効期限管理も行います。

Sessionは「ログイン情報を安全にする魔法」ではありません。セッションIDそのものを推測されにくくし、盗まれにくくし、不要になったら無効化する設計が必要です。

よくある勘違い

「Cookieにユーザー名があればログイン済み」ではありません。 ブラウザから届く値は利用者が変更できる前提で扱います。サーバー側で有効なSessionと照合し、認証済みかを判断する必要があります。
