READ IN 1 MINUTE

1分で読む説明

検索から来た人も、ここだけ読めば要点がつながるように書いています。

GET

対象リソースの表現を取得するためのメソッドです。GETはsafe、かつidempotentと定義されています。

POST

リソース固有の処理を依頼します。新規作成によく使われますが、POST=必ず作成という仕様ではありません。

PUT / DELETE

PUTは指定したリソースの状態をRequest contentで作成・置換する意味、DELETEは対象リソースの関連付けを削除する意味です。どちらもidempotentと定義されています。

safe / idempotent

safeは「クライアントがサーバー状態の変更を要求しない意味」、idempotentは「同じ要求を複数回送っても意図したサーバー状態への効果が同じ」という性質です。

COMMON MISUNDERSTANDINGS

よくある勘違い

「POSTは作成、PUTは更新とだけ覚えれば完全」API設計ではよくそう使いますが、HTTP仕様上の意味はもう少し一般的です。
「GETならサーバーでは一切何も変化しない」ログ記録など副作用が起こることはあります。safeは要求された意味に関する性質です。
