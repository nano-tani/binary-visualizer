HTTPメソッドは、サーバーに「何をしたいか」を伝える部分です。GET・POST・PUT・DELETEを切り替えて、リクエスト行・ボディ・サーバー処理の違いを確認します。

同じAPIに別のメソッドを送る

GET / POST / PUT / DELETE を切り替えてから「次へ」または「自動で見る」で流れを追えます。

GETで取得する開始前
GETは、指定したリソースを取得したいときに使われます。
クライアントAPIを呼び出す
Web API/users
HTTP REQUEST
ユーザーを取得サーバーは指定されたユーザー情報を返します。


4つの違い
GETリソースを取得する。通常はリクエストボディを使わず、URLやヘッダーで条件を伝えます。
POST新しいデータの作成や処理の実行に使われます。ボディを持つことが多いです。
PUT指定したURIのリソースを置き換える、または更新する用途で使われます。
DELETE指定したリソースを削除したい意図を伝えます。


安全性と冪等性
HTTPでは、メソッドごとに「同じ操作を繰り返したときどう考えるか」という性質があります。
GETsafe / idempotent
POST通常は非冪等
PUTidempotent
DELETEidempotent
safe は、仕様上サーバーの状態変更を目的としないこと。idempotent は、同じリクエストを複数回送っても、意図される最終状態が1回送った場合と同じになる性質です。


メソッド名だけで安全になるわけではない
HTTPメソッドは通信の意図を表す約束です。GETだから技術的に絶対データを変更できない、DELETEだから必ず削除される、という強制機能ではありません。実際の処理はサーバー実装と認証・認可によって決まります。
次にHTTPステータスコードを見ると、サーバーがこのリクエストに対して「成功・転送・クライアントエラー・サーバーエラー」のどれを返したかまでつながります。
